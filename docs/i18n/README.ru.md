Открытый источник репозитория модулей для экосистемы **KernelSU / Magisk / APatch**: одна конфигурация, два совместимых формата вывода — **ShizuSU / SukiSU-Ultra (маршрут A)** и **MMRL / BakaSU (маршрут B)** — как замена прекратившему работу официальному источнику `modules.kernelsu.org`.

Собирает модули с открытым исходным кодом, отобранные из **глобального списка из 1 532 записей**; версии и ссылки для скачивания автоматически пересобираются ежедневно.

## Возможности

- **Двухформатный вывод**: `modules.json` (нативная схема менеджера) + `json/modules.json` (протокол MMRL) — одно репозиторий работает с ShizuSU, KernelSU, SukiSU-Ultra, MMRL и BakaSU
- **Полностью автоматическое обслуживание**: GitHub Actions ежедневно в 00:30 UTC обновляет метаданные, последние релизы и прямые ссылки на скачивание с повторной подписью
- **Аудит порога открытости**: `tools/validate.py` проверяет каждый модуль по критериям «исходники доступны + лицензия + скачиваемый релиз»; результаты записываются в `audit.json` для прослеживаемости
- **Механизм подписей**: индекс и ZIP-архивы приватных модулей подписаны Ed25519; публичный ключ находится в репозитории для офлайн-проверки
- **Ручной + автоматический сбор**: три пути приёма — через Issue, автообнаружение по GitHub-темам и загрузка с телефона с одобрением
- **Приём, одобренный администратором**: модули с неясной лицензией принимаются после проверки администратором (`adminApproved`), прозрачно помечаются, риски оценивает пользователь

## Быстрый старт

### Менеджер ShizuSU / SukiSU-Ultra

Менеджер поддерживает переопределение источника репозитория в рантайме: в настройки («settings») записать ключ `module_repo_base_url` со значением Pages-URL этого репозитория:

```
https://qianyumeng0228.github.io/ShizuSU-Modules
```

### Официальный менеджер KernelSU (маршрут A)

Для менеджеров, поддерживающих формат списка `modules.json`, добавить источник репозитория:

```
https://qianyumeng0228.github.io/ShizuSU-Modules/modules.json
```

### MMRL

Добавить репозиторий в MMRL; URL может быть с завершающим `/` или без него:

```
https://qianyumeng0228.github.io/ShizuSU-Modules/
```

MMRL читает `json/config.json` и `json/modules.json`; собранные модули можно просматривать и устанавливать напрямую.

### BakaSU

В BakaSU «Настройки репозитория → + Добавить репозиторий»:

- **Формат API: обязательно выбрать `MMRL`**
- **URL сервера** (без суффикса `/json/modules.json`):

```
https://qianyumeng0228.github.io/ShizuSU-Modules
```

> **Не** выбирайте `KernelSU Modules API`: это протокол Registry. Этот репозиторий не предоставляет конечную точку `api/v1`, а BakaSU принудительно проверяет реальный SHA-256 для источников Registry, что приведёт к 404/ошибкам установки.

## Структура репозитория

```
modules.json                  # Маршрут A: каталог модулей (список, соответствует официальной схеме)
module/<moduleId>.json        # Маршрут A: детали каждого модуля (релизы / README / ссылки на скачивание)
json/config.json              # Маршрут B: описание репозитория MMRL
json/modules.json             # Маршрут B: индекс модулей MMRL
modules/<id>/track.json       # Маршрут B: определение track MMRL
modules/<id>/update.json      # Маршрут B: MagiskUpdateJson (версия/скачивание)
signatures/public.pem         # Открытый ключ Ed25519
signatures/modules.sig        # Подпись modules.json
signatures/<moduleId>.sig     # Подпись ZIP приватных модулей
audit.json                    # Результаты аудита порога открытости
catalog/candidates.json       # Кандидаты автообнаружения по темам
private/*.zip                 # Приватные модули (одобрены администратором)
compat/                       # Модули совместимости
```

Данные генерируются с помощью `build.py` (маршрут A) + `tools/build_mmrl.py` (маршрут B) + `tools/validate.py` (аудит) + `tools/sign.py` (подпись); схема маршрута A по полям совпадает с кодом парсинга менеджера SukiSU-Ultra / ShizuSU.

## Собранное содержимое

- **861 модуль** в индексе маршрута A; **794** устанавливаются напрямую через MMRL/BakaSU
- **19 категорий**: скрытие Root / Play Integrity, метамодули (движки монтирования), реализации Zygisk, оптимизация производительности, сетевые прокси, блокировка рекламы, аудио, шрифты/дисплей, резервное копирование и восстановление, Xposed/LSPosed, WebUI и др.
- **322 одобрены администратором** (`adminApproved`): лицензия вышестоящего проекта не объявлена или неясна — приняты после проверки администратором, каждая запись содержит `note`; риски оценивайте самостоятельно
- Источник данных: глобальная сводка модулей KernelSU (список из 1 532 записей без дубликатов)

## Критерии приёма

Чтобы попасть в индекс, модули должны соответствовать следующим условиям (подробнее в [CONTRIBUTING.md](https://github.com/qianyumeng0228/ShizuSU-Modules/blob/main/CONTRIBUTING.md)):

1. **Исходники доступны**: публичный репозиторий GitHub
2. **Лицензия**: распознаваемая стандартная открытая лицензия (SPDX); неясные лицензии проходят через одобрение администратора
3. **Скачиваемость**: последний релиз содержит скачиваемый ZIP
4. **Не сборки ядра**: репозитории с исходниками ядра / сборкой LKM не принимаются (репозиторий собирает только устанавливаемые модули)

Модули, не прошедшие критерии, помечаются как `unverified` (всё ещё отображаются со статусом «на проверке»); приватные модули без публичного репозитория одобряются администратором и помечаются `origin=manual`.

## Подача модуля

Любой из трёх путей:

1. **Подача через Issue (рекомендуется)**: открыть Issue по [шаблону подачи модуля](.github/ISSUE_TEMPLATE/module_submission.md) с указанием репозитория и URL релиза
2. **Автообнаружение**: `discover-modules.yml` ежедневно сканирует GitHub по темам (`shizusu-module` / `kernelsu-module` / `magisk-module` / `apatch-module`); кандидаты попадают в `catalog/candidates.json`
3. **Загрузка с телефона**: вход «Загрузка модуля» в менеджере ShizuSU → очередь проверки → одобрение администратора → автоматическое включение

## Механизм обновления

- **Ежедневная сборка**: в 00:30 UTC (08:30 по пекинскому времени) автоматически обновляются версии, ссылки на скачивание и статистика
- **Ручной запуск**: запустить workflow `Update module repo` на странице Actions репозитория
- Цепочка сборки: генерация маршрута A → аудит порога открытости → вывод MMRL → подпись → проверка схемы → синхронизация GitHub Pages

Любой менеджер, инструмент или сайт может использовать данные этого репозитория. Рекомендуемые способы:

An open-source module repository source for the **KernelSU / Magisk / APatch** ecosystem: one configuration, two compatible output formats — **ShizuSU / SukiSU-Ultra (Route A)** and **MMRL / BakaSU (Route B)** — replacing the discontinued official source `modules.kernelsu.org`.

It collects open-source modules filtered from a **1,532-entry global list**, with versions and download links rebuilt automatically every day.

## Features

- **Dual-format output**: `modules.json` (manager-native schema) + `json/modules.json` (MMRL protocol) — one repository works with ShizuSU, KernelSU, SukiSU-Ultra, MMRL and BakaSU
- **Fully automatic maintenance**: GitHub Actions rebuild metadata, latest releases and direct download links daily at 00:30 UTC, with re-signing
- **Open-source gate audit**: `tools/validate.py` verifies every module for "source reachable + license + downloadable release"; results are written to `audit.json` for traceability
- **Signature mechanism**: index and private module zips are Ed25519-signed; the public key ships with the repository for offline verification
- **Manual + automatic collection**: three submission paths — Issue submission, GitHub topic auto-discovery, and phone-side upload with approval
- **Admin-endorsed collection**: modules with unclear licenses are collected after administrator review (`adminApproved`), transparently marked, with risks assessed by the user

## Quick Start

### ShizuSU / SukiSU-Ultra Manager

The manager supports runtime repository override: write the key `module_repo_base_url` into the "settings" preference with the Pages URL of this repository:

```
https://qianyumeng0228.github.io/ShizuSU-Modules
```

### KernelSU Official Manager (Route A)

For managers that support the `modules.json` list format, add the repository source:

```
https://qianyumeng0228.github.io/ShizuSU-Modules/modules.json
```

### MMRL

Add the repository in MMRL; the URL may or may not have a trailing `/`:

```
https://qianyumeng0228.github.io/ShizuSU-Modules/
```

MMRL reads `json/config.json` and `json/modules.json`; you can browse and install the collected modules directly.

### BakaSU

In BakaSU "Repository Settings → + Add Repository":

- **API format: must select `MMRL`**
- **Server URL** (without the `/json/modules.json` suffix):

```
https://qianyumeng0228.github.io/ShizuSU-Modules
```

> Do **not** select `KernelSU Modules API`: that is the Registry protocol. This repository does not provide an `api/v1` endpoint, and BakaSU enforces a real SHA-256 check for Registry sources, which would fail with 404/installation errors.

## Repository Structure

```
modules.json                  # Route A: module catalog (list, matches official schema)
module/<moduleId>.json        # Route A: per-module details (releases / README / download links)
json/config.json              # Route B: MMRL repository description
json/modules.json             # Route B: MMRL module index
modules/<id>/track.json       # Route B: MMRL track definition
modules/<id>/update.json      # Route B: MagiskUpdateJson (version/download)
signatures/public.pem         # Ed25519 public key
signatures/modules.sig        # modules.json signature
signatures/<moduleId>.sig     # private module zip signature
audit.json                    # open-source gate audit results
catalog/candidates.json       # topic auto-discovery candidates
private/*.zip                 # private modules (admin-endorsed)
compat/                       # compatibility modules
```

The data is generated by `build.py` (Route A) + `tools/build_mmrl.py` (Route B) + `tools/validate.py` (audit) + `tools/sign.py` (signing); the Route A schema is field-aligned with the SukiSU-Ultra / ShizuSU manager parsing code.

## Collected Content

- **871 modules** in the Route A index; **804** directly installable via MMRL/BakaSU
- **19 categories** covered: Root hiding / Play Integrity, meta-modules (mount engines), Zygisk implementations, performance tuning, network proxying, ad blocking, audio, fonts/display, backup and rescue, Xposed/LSPosed, WebUI, etc.
- **324 admin-endorsed** (`adminApproved`): upstream license not declared or unclear — collected after administrator review, each entry carries a `note`; assess risks yourself when using
- Data source: KernelSU module global summary (1,532-entry deduplicated list)

## Collection Criteria

Modules must meet the following conditions to enter the index (see [CONTRIBUTING.md](https://github.com/qianyumeng0228/ShizuSU-Modules/blob/main/CONTRIBUTING.md)):

1. **Source reachable**: a public GitHub repository
2. **License**: a detectable standard open-source license (SPDX); unclear licenses go through admin endorsement
3. **Downloadable**: the latest release contains a downloadable zip
4. **Non-kernel builds**: kernel source / LKM build repos are not accepted (the repository only collects installable modules)

Modules failing the criteria are marked `unverified` (still displayed with a "pending review" state); private modules without a public repository are admin-endorsed and marked `origin=manual`.

## Submitting a Module

Choose any of three paths:

1. **Issue submission (recommended)**: open an Issue using the [module submission template](.github/ISSUE_TEMPLATE/module_submission.md) with the source repository and release URL
2. **Auto-discovery**: `discover-modules.yml` scans GitHub daily by topic (`shizusu-module` / `kernelsu-module` / `magisk-module` / `apatch-module`); candidates land in `catalog/candidates.json`
3. **Phone-side upload**: ShizuSU manager "Module Upload" entry → review queue → admin approval → auto entry into the repository

## Update Mechanism

- **Daily build**: UTC 00:30 (08:30 Beijing time) automatic update of versions, download links and statistics
- **Manual trigger**: run the `Update module repo` workflow from the repository Actions page
- Build chain: Route A generation → open-source gate audit → MMRL output → signing → schema verification → GitHub Pages sync
